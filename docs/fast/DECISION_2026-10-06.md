## 2. What the layer skip may be used for, and the evidence

Rule (full table of consumers in `docs/fast/LAYER_SKIP.md`): in Gemma 4 E2B and E4B the upper 20 and 18 layers
store no keys or values. A token without the output flag therefore reaches nothing through those layers except
things that read one row per token from them. Those readers are guarded: unmasked drafter export, exported
per-layer inputs, an eval callback, training, embedding inputs, per-sequence KV streams with several sequences
in a batch. In every guarded case the reference graph runs. With the Gemma 4 assistant the target switches to
the masked export, because that drafter shares the target's KV cache and only reads rows of output tokens.

Evidence (API-level tool `pi/fast/tests/fast_check.cpp`, built against the patched tree and against an
unpatched copy of the pinned source; nine scenarios: plain decoding, prompt chunks of 1-9 tokens, 511/512/513-token
prompts in different splits, reused context after truncation, two sequences in one batch, output flags on
non-final rows, draft-verify-rollback by hand, embeddings, batch widths 1-9):

| Pi 5, patch v7, against the unpatched build | E2B | E4B |
|---|---|---|
| All switches off: logit vectors bit-identical | 140 / 140 | 140 / 140 |
| Layer skip: logit vectors bit-identical | 137 / 140 | 137 / 140 |
| Layer skip: persistent KV state identical (digests) | 32 / 32 | 32 / 32 |
| Layer skip: argmax changes / token sequences that differ | 0 / 0 | 0 / 0 |
| Layer skip: worst KL on the three vectors that differ | 2.9e-4 | 3.6e-4 |
| Control, reference against itself, same tokens in another batch split: worst KL | 5.0e-4 | 9.3e-4 |
| Draft-verify-rollback scenario commits the plain greedy tokens | yes | yes |

The three vectors that differ are the 511-513-token prompts: with one query row left and at least 512 cache
cells, ggml's CPU flash attention takes its single-query path, which sums in another order. The reference shows
a larger difference between two ways of batching the same tokens, so this is inside the engine's own variation,
but it means "bit-identical logits" is not claimed.

Server level, greedy, one stream: the patched build produced the reference text in 115 of 115 comparisons on
2026-10-06 afternoon and in all 54 patched requests of the matched benchmark below (27 plain, 27 with the
drafter; English, Hebrew, German, code, prompts of 21-374 tokens).

Scope that is supported: text input, plain decoding, chunked prompts, context reuse, several sequences in a
unified KV buffer, non-final output rows, the Gemma 4 assistant with acceptance, rejection and rollback, the
non-flash attention path and a quantized KV cache (the last two on the desktop with the upstream version).
Not tested: image and audio input (falls back), LoRA and control vectors, GPU backends.
Not applicable: 26B-A4B and 31B (no shared-KV layers; the condition is false and nothing changes).

Reading it without mixing the causes:

- **The patch alone** (plain against plain): prompt processing 56.6 -> 147.4 tok/s, time to the first visible
  text x2.1-2.8 shorter (0.66 -> 0.30 s on short prompts, 3.5-6.1 -> 1.3-2.2 s on long ones), decode unchanged
  (7.45 -> 7.46 tok/s). Whole series 131.8 -> 120.6 s (-8.5 %); on the long prompts -19 to -26 % per request.
- **The drafter alone** (reference build): decode 7.45 -> 12.60 tok/s, series 131.8 -> 85.1 s (-35 %). This is
  upstream functionality and is not a result of the patch.
- **The patch on top of the drafter**: series 85.1 -> 73.1 s (-14 %); long prompts -35 to -44 % per request,
  because the saved prompt time is now a larger share. Decode 12.60 -> 12.82 tok/s (+1.7 %, the tail and chunk
  changes).
- **Both together** against reference/plain: 131.8 -> 73.1 s (x1.80).
- Repetitions agree within 1 %. No request was slower with the patch than without it. Peak memory is not higher
  (4765 against 4791 MB plain, 4964 against 5001 MB with the drafter).
- `--reasoning off` was checked before use: the server then renders `<|turn>user\n...<turn|>\n<|turn>model\n`
  without the `<|think|>` system turn and the model answers directly; the default and `--reasoning on` render
  the thinking prompt; `--reasoning-budget 0` keeps the thinking prompt and the reasoning then appears in the
  visible answer (`results/desktop-fast/reasoning-check/`). Thinking-enabled runs are reported separately (section 5).
