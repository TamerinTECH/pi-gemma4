## Gemma 4 26B-A4B architecture (config.json + GGUF header + llama.cpp src/models/gemma4.cpp)
30 layers, hidden 2816, vocab 262144 (tied), GELU-tanh. Every layer has a dense FFN (intermediate 2112, the "shared expert") AND an MoE block: 128 experts, top-8, softmax gating (router logits from rms_norm(attn_out)*scale), expert intermediate 704. Attention: 16 heads, head_dim 256; pattern 5 sliding (window 1024, 8 KV heads) : 1 global (2 KV heads, head_dim 512, K==V). Context 262144.
GGUF Q4_0 per-layer tensors: blk.N.ffn_gate_up_exps.weight Q4_0 [2816,1408,128] = 285.5 MB; blk.N.ffn_down_exps.weight Q4_0 [704,2816,128] = 142.7 MB; blk.N.ffn_down_exps.scale F32 [128]; router blk.N.ffn_gate_inp.weight F32 [2816,128] + .scale [2816]; dense blk.N.ffn_{gate,up,down}.weight Q4_0; attention blk.N.attn_{q,k,v,output}.weight Q4_0 + norms F32; token_embd.weight Q6_K. ONE expert of ONE layer = 2.23 + 1.115 = 3.345 MB; one layer's experts = 428 MB; all experts = 12.85 GB (89% of the file); non-expert ~1.6 GB (embd/out 0.61, attn 0.62, dense FFN 0.35). Experts are contiguous slabs along the last dim: expert e occupies bytes [e*nb2, (e+1)*nb2) from the tensor's data_offset (gguf.GGUFReader gives data_offset, shape, tensor_type, n_bytes; Q4_0 = 18 bytes per block of 32 weights). Worst-case expert bytes per generated token = 30*8*3.345 MB = 803 MB.

Verified facts that shape the build: (1) default repack copies every Q4_0 tensor out of the mmap into CPU_REPACK anonymous memory (llama-model.cpp:1849-1870 mmaps only the default buft). So the ONLY page-cache streaming mode at this commit is `-nr`/`--no-repack` (`--repack 0` in llama-bench): the whole file stays CPU_Mapped. (3) gemma4 dense FFN emits `ffn_norm-<il>` (gate/up input), `ffn_geglu-<il>` (down input, [21504,T]) and `ffn_out-<il>` (down output, pre post-norm); MoE routing tensors are `ffn_moe_topk-<il>` (I32 view [8,T], nb[1]=512) and `ffn_moe_weights_norm-<il>` (F32 [1,8,T], sums to 1; gemma4 uses norm_w=true); warmup routes to ALL experts (llama-graph.cpp:1473) so the probe sets params.warmup=false (`--no-warmup` is not a COMMON flag). - The Pi's Wi-Fi drops packets under load (66 % loss observed for ~15 min during a download + verification); keep SSH calls short, run anything longer than a minute with nohup on the Pi and poll its output; never assume a dropped SSH session means the job died.
- curl's --retry restarts from the first attempt's offset and truncated a 4.3 GB partial download; pi/adhoc/fetch_gguf.sh now loops separate `curl -C -` calls (resume from the current size). Any download code in pi/04_fetch_model.sh must do the same.
- Ad-hoc measurement tools already on the Pi in ~/pigemma: serve_measure.py (llama-server driver with per-request read_bytes/majflt/smaps logging, optional --balloon-gib and --extra for MTP), balloon.py (mlocked memory balloon, sudo, guards >= 2.5 GiB free, self-expires), sample_proc.py, bench_pi.sh, fetch_gguf.sh. Sources: pi/adhoc/.
